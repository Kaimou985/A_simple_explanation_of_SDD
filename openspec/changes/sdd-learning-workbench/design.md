## Context

网站围绕一次 OpenSpec 变更组织教学。用户可以从空白需求开始，也可以打开已有四类文档的月度销售分析示例。需要评审的是本变更目录中的文档。项目根目录的 `templates/` 则为网站运行时提供原模板。

## Goals / Non-Goals

**Goals:** 双栏教学工作区、四类 OpenSpec 产物、DeepSeek 多轮生成和评审、按文件展示本轮差异、可离线体验的预设示例。

**Non-Goals:** 执行实际数据分析、生成或运行应用代码、导入已有 OpenSpec 项目、持久化跨会话历史或公开部署。

## Decisions

1. **浏览器负责交互，Node 服务负责模型调用。** 本地首版采用原生浏览器界面和 Node HTTP 服务，减少运行依赖。浏览器将当前阶段、消息、近期对话和草稿交给本地服务，服务使用环境变量中的密钥调用 DeepSeek。
2. **保留原模板和产物依赖。** `templates/` 保存四份 OpenSpec `spec-driven` 原模板，既用于空白预览，也用于模型输入。Proposal 完成后可生成 Specs 和 Design。两者齐备后生成 Tasks。新建工作区起草的是新变更，同一未归档草稿内的修订沿用 `ADDED Requirements`。
3. **用一批文件更新表达一轮修改。** 模型输出一段对话回复和一个以相对路径为键的 Markdown 更新集合。省略路径表示保留该文件，空集合用于纯讲解、评审或追问。服务端检查允许路径、基本模板结构和前置产物，任一更新无效时拒绝整批结果。
4. **在当前页面会话维护草稿。** 浏览器为每个路径保存当前内容，并对比本轮修改前后的行。界面将新增和删除分别标出，列表提供文件定位。对话及 Markdown 以纯文本方式渲染。刷新页面会重开工作区。
5. **示例与实时模式共用界面。** 示例采用初始草稿和一组预设更新，提供稳定、可重复的教学结果。自由输入和多轮生成由 DeepSeek 实时模式处理。

## Risks / Trade-offs

- DeepSeek 可能超时、拒绝请求或返回无效结构。保留本轮输入和已有草稿，并提示重试或检查配置。
- 结构校验能发现缺失的标题、场景及前置文档。业务口径、方案取舍和验收覆盖仍由用户审阅草稿。
- 实时模式的需求和草稿会交给 DeepSeek 处理。本地示例适合体验无需上传内容的流程。
